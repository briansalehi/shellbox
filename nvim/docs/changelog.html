How to add an entry

Add a new section.release directly below this box, above the previous newest entry. Its heading is the ISO date; one div.entry per commit, carrying the short sha, the subject, a tag, and one sentence on why it landed — the reason, not the diff.

Tags are option for a vim setting, plugin for an addition, removed, and fix. Update the commit range chip in the header too. Full instructions sit in the HTML comment at the top of this file.

2026-09-04

No new plugins, only display settings: the interface had edges and transitions it was not drawing.

4426f1b The statusline lists the tab’s windows option

One global statusline can only name the window that has focus, so the splits without focus were left unlabelled. The windows component lists every window in the tab and highlights the active one. The alternative was a winbar heading each window, but a winbar is drawn outside the text area — winheight() is documented as excluding it — so naming panes that way costs one buffer line per window, and this costs none. Filenames only rather than the relative path shown before, because several paths at once do not fit the width; show_filename_only = false reverses that. Floating windows and the quickfix are skipped by the component, so telescope and trouble never appear in the list.

d845661 One statusline, not one per window option

Each window drew its own lualine bar, so a vertical split produced two half-width copies of the same rounded bar meeting at a seam in the middle of the row, and every extra window spent another line on it. laststatus=3 draws the bar once across the full width. It also changes how stacked windows are divided: nvim used the upper window’s statusline as the separator and now draws a real horizontal line in the WinSeparator grey instead of a coloured band. The cost is that the filename in lualine_c only ever describes the active window, so inactive splits carry no label. lualine reads laststatus during setup() to decide globalstatus, which is why options has to stay required before plugins in init.lua.

a24736d Rounded caps on the statusline option

The section separators were empty strings, so lualine’s mode, branch, filetype and location blocks met as flat rectangles and every colour change read as a seam instead of a transition. They now use the powerline caps, and the component separators within a section trade the ASCII pipe for the thin variant of the same shape. Rounded rather than angled, so the statusline, the float borders and the split edges are all the same decision. The glyphs come from the nerd font that the diagnostic signs and devicons already require, so nothing new has to be installed.

925ed12 Borders on the floats, edges on the splits option

Any float that did not configure a border of its own rendered without one, so lsp hover, signature help and diagnostics ran straight into the buffer behind them while clangd’s two floats were rounded. winborder is global, so a single option covers every one of them; telescope, cmp and which-key set border="none" on their own floats and keep it rather than gaining a second frame. Separately, ayu paints WinSeparator black against a near-black background, which meant splits had no visible line at all — it now takes FloatBorder’s grey so split edges and float edges read as the same interface. fillchars keeps nvim’s default box-drawing characters and changes only the three that are not: the ~ past the last line and the dots padding foldtext go blank, and removed diff lines are hatched instead of filled with dashes.

2026-09-03

A third coding agent, wired through the same terminal engine as the other two, and the two picker problems that turned up behind it.

c9b18cf The one-time fzf build, written down fix

The PackChanged hook can only fire for installs and updates that happen after it exists, so every machine whose plugins were already on disk still needs one manual make. That is now a per-machine step in the README, and the startup warning resolves the plugin path through vim.pack.get() and prints the command to run rather than only reporting that the load failed.

4372779 The fzf sorter was never enabled fix

telescope-fzf-native sat in the plugin list with nothing calling load_extension('fzf'), so telescope kept its own Lua sorter and this page claimed a native sorter that was not running. It is a C library and vim.pack has no build step, so the .so had never been compiled either. A PackChanged autocmd now runs make on install and update, and the load is wrapped in pcall so a missing library warns rather than failing quietly again.

13e008f vim.ui.select through telescope plugin

The cursor model picker returns 217 entries, and the builtin vim.ui.select renders those as a numbered cmdline list that has to be paged to reach anything. telescope-ui-select replaces the API with a dropdown, so the list is fuzzy-filtered. Registered as an extension rather than called directly, so the opencode picker and cmake-tools' generator, kit and preset prompts pick it up unchanged.

046412c cursor-agent as a third agent plugin

Cursor ships a terminal agent whose interface is the shape lua/agents.lua already expects: an argv, --model, --continue. So it needed no engine change, only a table entry and four keymaps. Its model picker is the plain form, label and --model <name> and nothing else, because cursor takes its instructions from .cursor/rules and AGENTS.md and so has no prompt flag to pair with a model.

2026-09-03

Filling gaps found by reading a third-party config against this one: git hunks, debugger values, todo routing, and three plugins that turned out to do nothing.

f739bc6 gitsigns, dap virtual text, todo-comments plugin

The plugin list carried a note reading gitsigns replaced by diffview, which conflated two different jobs: diffview is a window you open, gitsigns marks uncommitted lines as you type and gives per-hunk staging. dap-virtual-text puts scope values on the lines they belong to while stepping, which dap-ui only shows in a panel. todo-comments routes TODO and FIXME through the trouble list already in use.

6a3faec Inline diagnostics option

The diagnostic config set signs only, so reading any clang-tidy warning meant pressing gl first. virtual_lines = { current_line = true } has been builtin since 0.11 and renders the message under the cursor's line only, leaving the rest of the buffer uncluttered.

d4f664b Three plugins doing nothing removed

tagbar had no config and no keymap. dashboard-nvim was never setup(), so it never rendered — only a stray signcolumn autocmd referenced it. vim-commentary is redundant because gc and gcc have been builtin since 0.10 and behave identically.

2026-09-02

Two missing options and three plugins that add context the config had no way to show.

ebb0ceb Persistent undo option

Undo history lived in memory, so it died with the buffer. undotree had been re-added after an earlier commit dropped the option and the plugin together, leaving the plugin browsing only the current session. The default undodir needed no setting.

69031c9 Cursor context lines option

Jumps from gd, ]d and :cnext scroll the minimum needed to reveal the target, which regularly parked it on the last visible row with nothing beneath it. scrolloff = 8 keeps eight lines under every landing.

9513f6f vim-illuminate plugin

Other uses of the symbol under the cursor go grey with no keypress, replacing a reach for * or gr just to see where a variable is touched. Providers are lsp then regex: the treesitter provider needs nvim-treesitter.locals, which the main-branch rewrite does not ship.

3247b06 nvim-bqf plugin

cmake_executor is the quickfix executor, so a failed build opens the native quickfix window on its own. bqf previews each entry in place while scrolling the list, instead of jumping to find out what an entry is. trouble covers the same entries but only behind \xq.

7c0f30f nvim-treesitter-context plugin

Pins the enclosing function and loop to the top of the window while scrolling a long member function. max_lines defaults to no limit, which nested C++ would use to fill the window, so it is capped at 3 and switched off in windows under 20 rows.

Outside the config

tree-sitter-cli, 2026-09-03

The parser directory was empty. Only nvim's bundled parsers existed — c, lua, markdown, vim, vimdoc, query — so cpp, cmake, python and rust had no treesitter at all and every launch silently retried a failing install. Installing the CLI built all four. C++ had been running on regex highlighting. Not a config change, but the config depended on it.

GitHub mirror, 2026-09-02

A repo-scoped deploy key at ~/.ssh/shellbox_mirror_ed25519, an ssh alias github-shellbox, and the github remote repointed at it. Scoped to this repository rather than the account, so a passphraseless key on a production box cannot reach anything else.
